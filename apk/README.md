# KOMA для Android (АПК-обёртка)

Обёртка вокруг той же читалки `koma-web.html`: WebView + **локальное
распознавание в фоне** + голоса. Одна кодовая база с браузерной версией, поэтому
исправления в читалке сразу приезжают в АПК — без переустановки.

Движок распознавания ОДИН — те же модели ONNX, что в первой читалке (Yomikai):
детектор находит облачка, распознаватель читает строки, всё считается на
телефоне. Облачного движка (Google Lens) в сборке больше нет: он не распознавал
страницу сам, а требовал открыть сайт в отдельном окне и перенести текст руками
(удалён 04.11 по прямой просьбе).

## Что внутри

| Файл | Что делает |
|---|---|
| `app/src/main/java/net/koma/reader/MainActivity.kt` | WebView, постоянный адрес страницы, выбор файлов моделей, «назад» внутри читалки, тихое автообновление при старте |
| `.../OcrEngine.kt` | локальный движок распознавания (ONNX, в фоне) |
| `.../KomaAppBridge.kt` | `window.KomaApp`: версия и «Проверить обновление» |
| `.../KomaSpeechBridge.kt` | **голос**: нативный Android TTS за мостом `KomaSpeech` (в WebView нет Web Speech API) |
| `.../Updater.kt` | скачивание `koma-web.html` с GitHub, проверка, атомарная замена |

## Почему адрес страницы постоянный

Читалка отдаётся не из `file://`, а по адресу
`https://appassets.androidplatform.net/web/koma-web.html` через
`WebViewAssetLoader`. Это важно:

* **IndexedDB привязан к источнику.** Модели (≈12 МБ), книги, настройки и словарь
  живут именно там. При обновлении меняется только файл, источник остаётся тем
  же — библиотека не стирается.
* `file://` в WebView не даёт IndexedDB и ломает `fetch`.

Файл берётся из `filesDir/koma-web.html`, если он есть (обновлённая версия), иначе
из `assets/koma-web.html` (встроенная). При отсутствии интернета работает
встроенная.

## Как работает распознавание

Страница зовёт нативный мост `window.KomaOcr` → `OcrEngine.kt`: детектор находит
облачка реплик, распознаватель читает строки, готовый текст возвращается
репликами. Всё считается на телефоне, в фоновом потоке; если нативный путь
почему-то недоступен, страница сама переходит на WASM-модели (тот же ONNX в
странице) и пишет причину в состояние — чтение не пропадает.

## Голос: почему мост, а не speechSynthesis

В Android WebView **нет Web Speech API** — `speechSynthesis` там просто нет. 28.10
на телефоне это выглядело так: «Скрипты страницы не выполнились», тост
«speechSynthesis is not defined» и пустая библиотека, потому что первый же вызов
голоса обрывал запуск страницы.

Теперь строку произносит системный движок Android (тот, что в «Настройки →
Синтез речи»), а страница говорит с ним только через фасад `VOICE`:

* `KomaSpeech.voices()` → список голосов в формате Web Speech;
* `KomaSpeech.speak(text, rate, lang, voice, id)` → речь;
* события `start` / `end` / `error` приходят в `window.__komaSpeechEvent(id, тип, данные)`.

Отметка «прочитано» ставится по `start`, переход к следующей реплике — по `end`,
ошибка движка показывается текстом. Пауза: у Android TTS её нет, поэтому в АПК
пауза = стоп, а продолжение начинает текущую реплику заново (и об этом сказано
тостом). В браузере остаётся прежний Web Speech с настоящей паузой.

## Сборка

### На GitHub (рекомендуется)

Actions → **сборка АПК** → Run workflow. Через ~5 минут в артефактах лежит
`koma-reader-debug.apk`. Push тега `v1.9.31` дополнительно кладёт APK в Releases.

### Локально

```bash
cp ../koma-web.html app/src/main/assets/koma-web.html   # или полагаемся на таск copyWeb
gradle assembleDebug        # Android SDK 34, JDK 17
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Своя подпись (для публикации)

Сейчас `release` подписывается отладочным ключом, чтобы APK ставился сразу.
Для Play/раздачи:

```bash
keytool -genkeypair -v -keystore koma.jks -alias koma -keyalg RSA -keysize 2048 -validity 10000
```

и в `app/build.gradle.kts` заменить `signingConfig` на свой (файл ключа в
репозиторий не класть).
